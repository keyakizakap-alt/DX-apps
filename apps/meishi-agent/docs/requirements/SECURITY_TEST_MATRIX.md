# セキュリティ要件 / 脅威・テストマトリクス

> 脅威モデルは開発中に更新する。OWASP MASVS/MASTGをチェックリストとして参照し、**文字だけの指示は実行時の権限制御ではない**ことを前提に自動テストとコードで強制する。

| ID | ケース / 期待結果 | 自動化・実証方法 | Go/No-Go |
|---|---|---|---|
| SEC-01 | SQLCipherファイルを鍵なしで復号できない | Native実機で暗号化DBファイルを取り出して検査 | 必須 |
| SEC-02 | 画像原本・サムネイル・一時キャッシュが平文で放置されない | アプリ領域/バックアップ領域を検査 | 必須 |
| SEC-03 | VMK/APIキー/復旧キーがlocalStorage、ログ、Git、同期DBに平文で残らない | ソース/ストレージ/ログ/シークレットスキャン | 必須 |
| SEC-04 | AAD・nonce・鍵バージョン違反は復号失敗 | 既知ベクトル+改ざん・鍵違い・リプレイケース | 必須 |
| SEC-05 | iPhone↔Webで暗号文の相互復号が一致 | Native/Webで同じテストベクトルを実行 | 必須 |
| SEC-06 | サーバーへ氏名/メール/電話/名刺原本・復号鍵を送らない | 通信キャプチャ、バックエンドログ検査 | 必須 |

| SEC-16 | Offline更新→同期競合→両者の元データが保持される | 同時編集・再接続E2E | 必須 |
| SEC-17 | 復旧キー紛失時の安全な回復不能性が説明される | UI/ドキュメント確認 | 必須 |

| SEC-19 | テスト名刺・資格情報がCIに漏れない | GitHub Actionsや`.env.example`確認 | 必須 |
| SEC-20 | 第三者SDKによる予期せぬ画像/文字列外部送信がない | SDKネットワーク通信と権限レビュー | 必須 |

## UIに実装する保護説明
- 同期暗号化が未検証なら、バッジに「同期済み」「安全」を表示しない。
- ブラウザはXSS/拡張機能/端末侵害まで絶対的に保護できないことを説明。
- Face IDは鍵アクセスの補助であり、鍵復旧の代替ではない。
- リモートログアウトでは、すでに復号されオフラインにある端末のデータ消去を保証できない。
- 外部AIに許可した情報はE2EEの保護領域を出るので、モデル側の保持・学習利用・地域等は契約と実仕様を確認し、未確認なら送信不可。

## テスト成果物の型

```text
[ID] SEC-xx
[platform] iOS real device / Android real device / Windows Chrome / CI
[build] commit SHA, Expo SDK, OS version
[command/method] 実行した具体的手順
[result] PASS / FAIL / BLOCKED / NOT_TESTED
[evidence] logs without PII / sanitized test screenshot / sanitized packet summary
[open issues] 課題と再試験条件
```

## 実装の即時差し戻し条件
平文個人情報のクラウド送信、未承認外部AI送信、固定鍵/nonce、誰でも復号できる同期API、RLS無効化、共有ストレージへの画像平文出力を検出した場合は、その機能を無効化し `NO-GO` と記録。
