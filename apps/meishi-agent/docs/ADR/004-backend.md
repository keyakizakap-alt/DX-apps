# ADR-004 同期バックエンド：自前の最小Nodeサーバー（認証・所有者認可・暗号文のみ）

- 日付: 2026-10-21 / 状態: 採用（MVP・検証用）。本番運用先は未決定（ユーザー判断）

## 決定
`server/`（Node 22.18+/24、`node:http` + `node:sqlite`）。機能はメールOTP認証、セッション、端末一覧/失効、復旧エンベロープ保管、暗号文の push/pull（revision・変更シーケンス・tombstone）、暗号化画像Blob、外部AIプロキシ（同意ハッシュ必須）、Webビルド配信（CSP等）。

## 理由
- 指示書の第一候補 Supabase（Auth + Postgres RLS + Storage）は**アカウント作成・プロジェクト発行・課金設定が必要**で、このセッションでは実行できない（ユーザー操作が必要）。
- 自前サーバーなら、所有者認可・平文非受信・競合検出を **このリポジトリ内で自動試験** できる（`tests/integration/sync-e2ee.test.ts`、`tests/security/server-auth.test.ts`、E2EでサーバーDBを直接走査）。

## 比較
| 案 | コスト | 可用性 | 運用負荷 | RLS/認可 | 判断 |
|---|---|---|---|---|---|
| 自前Node + SQLite（採用） | VM/コンテナ1台分 | 単一インスタンス。バックアップ・冗長化は運用者が用意 | 中〜高（パッチ・バックアップ・監視） | アプリ層で `account_id` をセッションから付与（クライアント入力を信用しない） | MVP検証用に採用 |
| Supabase | 利用量比例（無料枠あり、要確認） | マネージド | 低〜中 | Postgres RLS | 本番候補。移行時は同じAPI契約を Edge Functions/RLS で実装 |
| Cloud Run + マネージドDB | 利用量比例 | マネージド | 中 | アプリ層 | 本番候補 |
※各社の料金・SLAは本セッションでは未調査（推測で記載しない）。本番選定時に公式価格で算定すること。

## サーバーが受け取る/保存するもの
- 保存: アカウントID、**メールのHMAC**（平文メールは保存しない。OTP送信時のみメモリ上）、端末ラベル（例 "iPhone Safari"）、セッションのハッシュ、オブジェクトID・revision・削除フラグ・**暗号文**、暗号化画像、同意ハッシュ。
- 受け取らない: 氏名・会社・メール・電話・OCR本文・名刺画像の平文・VMK・復旧キー（E2Eで実測）。
- ログ: メソッド・ルート・ステータス・所要時間のみ（本文・クエリ・メールは出力しない）。

## 未実装・制約
- メール送信: 開発用メーラー（OTPをサーバーのコンソールに表示）のみ。本番はメール送信サービスの契約・設定が必要（USER_ACTIONS）。
- 水平スケール: SQLite単一ファイル。複数インスタンスにはDB移行が必要。レート制限はインスタンス内メモリ。
- 容量上限: 既定で1アカウント10万オブジェクト・画像1GiB（超過は413 `quota`、端末側の変更は保持）。
