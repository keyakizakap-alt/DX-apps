# ADR-003 鍵管理・復旧・端末追加

- 日付: 2026-10-21 / 状態: 採用

## 鍵の階層
- **VMK**（保管庫マスター鍵, 32byte）: 端末で生成。生のバイト列は生成/解除の瞬間だけメモリに置き、直後にゼロ埋め（JSエンジンのコピーまでは消せない点は限界として明記）。
- **復旧キー**: 32byte乱数 + SHA-256由来16bitチェックサム、Crockford Base32（`MK1-XXXXX-…` 11ブロック）。高エントロピーなので HKDF で直接ラップ鍵を導出（パスワード用KDFは不要）。非正規表記（パディングビット）も拒否。
- **復旧エンベロープ**: VMKを復旧キー由来鍵で AES-GCM ラップしたもの。端末とサーバーに保存（サーバーは復号不能）。
- **Web端末パスコード（任意）**: PBKDF2-HMAC-SHA256 **600,000回**（OWASP Password Storage Cheat Sheet の推奨値、2026-10-21確認, https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html 公式）＋ **非抽出CryptoKey（端末鍵, IndexedDB）** の二重ラップ。両方がないと解除できない。10回失敗でパスコードラップを削除。
- **iOS/Android**: SQLCipherのDB鍵を SecureStore（`WHEN_UNLOCKED_THIS_DEVICE_ONLY`）に保存。生体認証解除は VMK を `requireAuthentication: true` で保存（**実機未検証**）。

## 認証と復号の分離
- サインイン（メールOTP）はアカウントの確認のみ。名刺の復号には復旧キー（または端末ローカルのパスコード/生体）が必要（SEC-08: 統合試験で確認）。
- 新端末の追加 = サインイン → サーバーの復旧エンベロープ取得 → 復旧キーで解除。既存端末からの承認方式（QR等）は未実装。

## 失敗・紛失時
- 復旧キー紛失 + 全端末喪失 = **復元不能**（ゼロ知識設計のため）。UIで作成時に明示（SEC-17）。
- 端末のログアウト（サーバー側セッション失効）は、既にオフラインで復号済みの端末のデータ消去を保証しない（UIで明示）。
- 解除失敗: 3回目から指数バックオフ（2s,4s,…最大5分）。これはクライアント側の抑止であり、端末を奪われた攻撃者がブラウザ保存領域を直接解析する場合の防御にはならない（復旧キーは総当たり不能な強度で、パスコードはPBKDF2+非抽出鍵で保護）。
