# 脅威モデル（STRIDE）

- 更新: 2026-10-22（Vercel＋Neon・Resend を追加）
- 保護対象:
  - 名刺の内容（氏名・会社・連絡先・画像・OCR本文・会話メモ）
  - 保管庫マスター鍵（VMK）
  - 復旧キー
  - セッション
- 信頼境界:
  - ① 端末（解除中のメモリ）
  - ② 端末の保存領域（IndexedDB / SQLCipher）
  - ③ ネットワーク
  - ④ 同期サーバー
  - ⑤ 外部AI提供元
  - ⑥ ビルド・依存パッケージ
  - ⑦ ホスティング・DB・メールの委託先（Vercel / Neon / Resend）

## 攻撃者と前提
| 攻撃者 | できること | 主な対策 |
|---|---|---|
| A1 サーバー運営者・侵入者 | DB・ログ・通信の閲覧、暗号文の改ざん・差し替え・古い版の再送 | E2EE（端末で暗号化、サーバーは暗号文のみ）、AADでID結合、版番号による巻き戻し拒否 |
| A2 ネットワーク盗聴・中間者 | 通信の傍受・改変 | HTTPS必須（WebCryptoは安全なコンテキストのみ）、HSTS、`__Host-` Cookie |
| A3 他のアカウント利用者 | 他人の同期データの取得・上書き | 所有者はセッションから決定、全クエリを `account_id` で限定、端末ID詐称は403 |
| A4 悪意あるWebサイト | CSRF、DNSリバインディング、iframe埋め込み | カスタムヘッダー必須＋Origin検査、Host許可リスト、`frame-ancestors 'none'`、SameSite=Strict |
| A5 XSS / 悪意ある依存パッケージ | 解除中のデータ・鍵の窃取、任意スクリプト実行 | 厳格なCSP（eval・インライン禁止）、Trusted Types（許可したスクリプトURLのみ）、COOP/COEP、非抽出鍵、依存監査ゲート |
| A6 端末の拾得・盗難（画面ロックなし） | アプリを開く、保存領域を解析 | 自動ロック、画面非表示時のロックとカバー、鍵は保存しない（Webは復旧キーかPBKDF2＋非抽出鍵）、SQLCipher（ネイティブ） |
| A7 肩越しののぞき見・画面共有 | 復旧キーや名刺を見る | 復旧キーは既定で伏せ表示、画面切替時のカバー、iOSアプリ切替画面のぼかし、スクリーンショット防止（ネイティブ） |
| A8 名刺・メモに書かれた悪意ある文章（プロンプトインジェクション） | AIに送信・削除・共有をさせる | AIは読み取り専用4ツールのみ、文書由来の呼び出しを拒否、外部送信は型で項目制限＋都度同意 |
| A9 外部AI提供元 | 送られた内容の保持・学習 | 既定OFF、無料でも学習しない契約の提供元のみ（Groq）、ZDR必須、氏名・会社・部署を伏せ字化、メール・電話・画像は送れない |
| A11 委託先（ホスティング・DB・メール） | アクセスログのIP・パス、DB上の暗号文とメタデータ、送信時のメールアドレスの閲覧 | 名刺は E2EE で読めない、メールはDBに HMAC のみ、ログに本文・メール・クエリを出さない、委託先と範囲をプライバシーポリシーに明記 |
| A10 総当たり | OTP・パスコード・復旧キーの推測 | OTPは5回失敗で無効、1日10回まで、IP単位の制限。パスコードはPBKDF2 60万回＋非抽出鍵＋10回で無効化。復旧キーは256bit |

## STRIDE別の対策と根拠
| 分類 | 脅威 | 対策（実装箇所） | 検証 |
|---|---|---|---|
| S なりすまし | 他人のアカウントで同期データを取得 | メールOTP（HMAC保存・5回・10分・1日上限）、256bitセッショントークン（ハッシュ保存）、無操作14日・最長30日で失効、端末ごとの失効 | `server-auth.test.ts` |
| S | サインインだけで名刺を読む | 認証と復号を分離（復旧キーが必要） | `sync-e2ee.test.ts` SEC-08 |
| T 改ざん | サーバーによる暗号文の書換・差替・巻き戻し | AES-GCM＋AAD（保管庫・オブジェクト・用途・鍵版）、平文の `version` で巻き戻し拒否 | `crypto-vectors.test.ts`、`sync-e2ee.test.ts` SEC-04 |
| T | 端末の操作履歴を書き換えて痕跡を消す | 監査ログのハッシュチェーン（`verifyAudit`）、画面で検証結果を表示 | `client-hardening.test.ts`、E2E |
| T | 同期の競合で一方の編集が消える | revisionによる楽観的競合検出、「両方残す」、無言の上書きなし | `sync-e2ee.test.ts` SEC-16、E2E |
| R 否認 | 平文エクスポートや削除の事実を否認 | 監査ログに件数・結果を記録（個人情報なし、ハッシュチェーン） | SEC-14 |
| I 情報漏えい | サーバー・ログに平文 | E2EE。ログはルート・ステータス・時間のみ。メールはHMACで保存 | 統合試験・E2EでDBとログを全件走査 |

| I | 画像の一時ファイル・EXIF（位置情報） | 再エンコードでEXIF除去、撮影一時ファイルの削除（ネイティブ） | Web: E2E。ネイティブは未検証 |
| I | クリップボードに残る | 60秒後に消去（ネイティブは内容を比較、Webはフォーカス中に消去） | 手動確認のみ |
| I | 画面ののぞき見・アプリ切替画面 | 伏せ表示、カバー、`preventScreenCaptureAsync`、`enableAppSwitcherProtectionAsync` | Web: E2E（伏せ表示）。ネイティブは未検証 |
| D サービス妨害 | 大量リクエスト・大量データ・低速接続 | IP全体600回/分、各操作の制限、本文サイズ上限、容量上限（件数・画像）、ヘッダー/リクエストのタイムアウト | `server-auth.test.ts`（容量・OTP上限） |
| E 権限昇格 | AIが削除・送信・統合を行う | 読み取り専用ツールの許可リスト、文書由来の呼び出しを拒否、引数をZodで検証 | SEC-11 |

## 残るリスク（受容または今後の対応）
1. **解除中のメモリ**: XSSや端末のマルウェアが成立すると、解除中に復号済みのデータは読まれ得ます。これはブラウザの限界で、画面でも説明しています。対策として、自動ロック・画面非表示時のロック・Trusted Typesで成立可能性を下げています。
2. **端末の保存領域の巻き戻し**: 端末を物理的に掌握した攻撃者は、IndexedDBを古い暗号文に戻せます。改ざん（復号）はできません。巻き戻し検知には、端末外の信頼できる記録が必要です。
3. **監査ログのハッシュチェーン**: 鍵のないハッシュです。端末の完全な掌握者はチェーンを作り直せます。検知できるのは中途半端な編集だけです。
4. **解除失敗の遅延**: 端末内の状態として保存しているため、保存領域を直接操作できる攻撃者には効きません。復旧キーは256bitで、パスコードはPBKDF2＋非抽出鍵のため、オフラインでの総当たりは困難です。
5. **外部AI**: 伏せ字化は固有名詞の置換です。会話メモ内の言い換え（例:「あの社長」）や、文脈から人物を推定される可能性は残ります。送信前に本文を表示し、利用者が確認する設計にしています。
6. **ネイティブ（iOS/Android）**: SQLCipher・Keychain・画面保護・一時ファイル削除は実装済みですが、実機では未検証です（SECURITY_REPORT 参照）。
7. **サーバーの運用**: 自前サーバーではバックアップ・監視・パッチ適用は運用者の責任です（ADR-004）。Vercel＋Neon では、回数制限（IP 毎分）が関数インスタンス単位のため、多数のインスタンスに分散した総当たりには上限が緩くなります。OTP は1日10回・5回失敗で無効・10分で失効を DB で判定するため、確認コードの総当たりは引き続き困難です（ADR-007）。
8. **第三者レビュー**: 暗号と鍵管理について、外部の専門家によるレビューはまだ受けていません。
