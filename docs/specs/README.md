# 仕様書（docs/specs）

機能開発ごとに1ファイル、ここに仕様書を置く。雛形は [\_TEMPLATE.md](./_TEMPLATE.md)。

## ルール

1. 機能開発に着手する前に `docs/specs/<機能名>.md` を作り、`## 完了条件` を書く。
2. 完了条件には、誰が判定しても同じ結果になる基準だけを書く。各項目はチェックボックス（`- [ ]`）にし、判定に使うコマンドかファイルパスをバッククォートで囲む。
3. 「適切に」「正しく」「問題なく」など、判定する人によって結果が変わる言葉は使わない。
4. 完了条件をすべて満たしたら `- [x]` にする。満たしていない項目が残る間は完了と報告しない。
5. 形式は `npm run lint:specs` で検査される（`npm test` にも含まれる）。失敗したら、出力の「直し方」に従う。

## 書き方の例

| 種類         | 良い例                                                  | 悪い例               |
| ------------ | ------------------------------------------------------- | -------------------- |
| テスト       | ``- [ ] `npm test` が終了コード0で終わる``          | テストが問題なく通る |
| ファイル生成 | ``- [ ] `output/report.pdf` が生成される``              | 資料がちゃんとできる |
| 出力内容     | ``- [ ] `node cli.mjs --help` の出力に `Usage` を含む`` | ヘルプが適切に出る   |
| 数値         | ``- [ ] `dist/app.js` のサイズが 200KB 以下``           | 十分に軽い           |
