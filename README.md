# ANGLE Review

OpenRouterで17の専門工程を分担し、企画から振り返りまで進める日本語コンテンツ制作アプリ。HOTL（Human-on-the-loop）により通常処理は自動化し、根拠不足・取材待ち・実績待ちで停止する。

## Vercelへの反映

ソースは `DX-apps` の `main`、リポジトリ直下に配置しています。以前の `angle-review/` をRoot Directoryに指定している場合は空欄に戻してください。

1. Vercelで `keyakizakap-alt/DX-apps` をImport。Production Branchは `main`、Root Directoryは空欄（リポジトリ直下）、Framework Presetは **Other**。
2. Build Commandは `npm run build`、Output Directoryは `public`。`vercel.json` にも設定済み。画面とAI APIはFunctionで提供します。
3. 運営者がSettings → Environment Variablesに `OPENROUTER_API_KEY` を秘密情報として設定。Production / Previewの必要な環境に適用してください。利用者向けの入力欄はなく、ブラウザから送られたキーはAPIで拒否します。GitHubやフロントエンドにキーを記載しないでください。
4. 設定変更後にRedeploy。`APP_ACCESS_PASSWORD` と `SESSION_SECRET` は不要で、既存の設定も削除できます。APIキー未設定でも画面と基本チェックは利用でき、AI実行はできません。
5. 発行されたURLを開けば、そのまま利用できます。資料の分類と送信同意を確認して制作フローを開始してください。

`SITE_ORIGIN` は独自ドメインを使う場合の正確なHTTPSオリジンを指定。通常のVercel URLは `VERCEL_URL` / `VERCEL_PROJECT_PRODUCTION_URL` を検証します。旧ホスティングの `SITE_ORIGIN` を流用しないでください。`ALLOWED_MODELS` は省略時に標準の2モデル。`ALLOWED_USER_EMAILS` はSites専用です。

Vercel版はパスワードもログインCookieも使わない公開アクセスです。利用者のAI実行は運営者のOpenRouterアカウントに課金されます。OpenRouter側の支出上限とVercel側のアクセス制限・レート制限を運営者が設定してください。アプリのレート制限はインスタンス単位の共通枠（同時3件・毎分60件）であり、アカウント全体の課金上限ではありません。入力資料は利用者ごとの画面メモリで扱い、他の利用者から参照する一覧や保存機能はありません。

VercelのGitHub連携が済んでいれば、以降の `main` へのコミットが本番反映の起点になります。ビルドの成功と実際の有料AI実通信は別の確認です。

## 利用方法

「制作フロー」でテーマ・読者・目的・資料を入力し、「資料の取り扱い」で機密区分と送信同意を確認する。運営者がサーバーの `OPENROUTER_API_KEY` を設定し、キーはブラウザに送信しない。利用者はAPIキーを入力・変更できない。

企画・調査、取材設計、依頼下書き、取材素材整理、初稿、事実・引用、表記・校正、構成、リライト、最終照合、タイトル、画像指示、入稿準備、SNS文案、アーカイブ、分析を実行する。取材前でも開始でき、文字起こしを追加して再開できる。校正の3エージェントは並行実行し、失敗時は成功済み工程を保持する。モデルとAI接続は運営側で管理し、利用者向けの設定画面には表示しない。

## HOTL

検証できない根拠、最終の確認候補、要確認の原稿が残る場合は公開準備の前に停止。監督者が原稿と根拠を確認し、10文字以上の判断理由を記録して再開する。公開用HTMLの保存は別途承認が必要。承認は原稿・タイトル・SNS・公開準備のハッシュに紐づき、変更後は無効となる。

メール送信、実際の取材、画像の取得・加工、外部校正者の承認、WordPress登録、SNS投稿、Google Analytics取得は直接接続していない。提案・下書き・HTMLを用意し、外部への実行は人が行う。録音の文字起こしはPlaud Note等で作成して入力する。

## 情報管理

資料はブラウザのメモリとAPIリクエスト処理中のメモリにのみ保持し、自動保存、localStorage、記事本文のサーバーログは使わない。明示的に保存したJSONにはマスキング後の資料・成果物・判断記録が含まれるため、利用者が管理する。画面の消去はアプリからの参照削除であり、OS・ブラウザの物理的な完全消去を保証しない。

「機密・外部送信禁止」はサーバーでも送信拒否する。「社内限定」はメール・電話番号のマスキングを必須とし、Web検索は禁止。非公開の人名や案件名は追加のマスキング語句を指定する。自動検出は全個人情報を識別するものではない。送信前プレビューと組織の情報分類・利用許可が必要。

OpenRouterには `provider.data_collection: deny` と `provider.zdr: true` を要求し、条件に合うモデル提供元がない場合は失敗させる。これは提供元のルーティング制限であり、OpenRouter・検索サービス・ホスティング事業者の保持方針や契約をアプリから保証するものではない。組織で事業者の契約・地域・保持条件を確認する。検索は公開情報のみ、任意の追加料金機能。モデル料金はOpenRouterアカウントに発生し、APIが返した使用量・費用のみを表示する。

## 実行・ビルド

Node.js 24を推奨。依存パッケージの追加インストールは不要。

- `npm start`: http://127.0.0.1:4173 の開発用プレビュー。開発サーバーだけがローカルの仮の本人識別を付与する。外部公開しない。
- `npm test`: 根拠検証、修正重複、情報管理、認証、同一生成元、HOTL、監督承認、再開、改ざん検知の回帰確認。
- `npm run build`: Cloudflare Workers互換の `dist/server/index.js` を生成。

Vercel版はパスワードなし。Sites版は従来の本人限定アクセスと `ALLOWED_USER_EMAILS` を使用。環境設定は `.env.example` を参照。実キーをGitHubにコミットしない。GitHubのリポジトリ直下をソースの保存先とする。

## 制約と検証

根拠検証は引用IDと引用文の存在を確認するもので、事実の正確性・意味の一致を保証しない。判断ログはメモリ内のハッシュ連鎖で、署名済みの改ざん不能な監査基盤ではない。レート制限はWorkerインスタンス単位で、アカウント全体の課金上限の代替ではない。OpenRouterキー側にも支出制限を設定する。

有料モデルとの実通信は実キー設定後に確認する。自動テストの正常なモデル応答はモックである。サンプルは架空、編集ルールは実際の媒体規定ではない。実際の記事3〜10本で作業時間、修正往復数、重大な見落とし、不要な指摘を計測する。


## ダッシュボードと監督・通知（2026-10）

白・ネイビー・コーラルを基調とする3列のダッシュボードで、現在の制作の進捗、確認待ち、根拠照合、専門チームの活動を表示します。未実施の工程や架空のチームメンバー・実績を完了として表示しません。制作ナビは工程の状態から次の作業を提示し、17の専門工程が成果物を引き継ぎます。ナビ自体はルールによる監督制御であり、別のモデルによる自由なツール選択ではありません。

タスク検索、制作ブリーフのテンプレート、公開予定日、編集メモを追加しました。すべてページ内メモリのみで、再読み込みやページ終了で消えます。編集メモと予定日はAIへ送信しません。共同編集・外部カレンダー連携・公開予約には対応していません。

人の確認、取材資料、公開用データの承認、実績、処理の停止が発生すると通知センターに表示します。「ブラウザ通知を有効にする」を押してOS/ブラウザの許可を得た場合のみ、ブラウザ通知を出します。通知本文は定型文で、原稿・資料・個人名は含みません。権限が拒否された環境でも画面内の通知は利用できます。通知をクリックすると該当箇所へ移動します。通知の重複を防ぎ、原稿の修正後に再度確認が必要になった場合は新しく通知します。

**通知と制作処理はページが開いている間のみです。** ブラウザを閉じた後のバックグラウンド処理・メール・Slack・Web Pushは未実装です。通知記録は最大30件をメモリ内で保持し、「資料と成果物を消去」で消します。ブラウザ通知は利用環境やOS設定により届かない場合があり、画面内の確認待ちを併用してください。

制作ごとのAI呼び出しは再開・失敗分を含め48回までに制限し、上限で停止します。これはブラウザ上の実行制御であり、サーバー全体の課金上限・匿名利用の濫用対策を代替しません。既存のサーバーでの同時実行数・リクエスト数制限、外部送信の同意・マスキング・ZDR指定・原稿改訂時の承認失効を維持しています。APIキーは引き続きサーバー環境変数のみです。

追加検証: `node tests/dashboard-browser.mjs` と `node tests/workflow-browser.mjs`。AIとブラウザ通知はモックを使用し、有料APIの実通信は含みません。


## 編集者向けの入力・進捗画面（2026-10-03）

記事プロジェクトの最初の必須項目はテーマ・読者・目的の3つです。資料と公開後の実績は別の折りたたみ欄に分けています。業務の状態を表す「準備中」「取材待ち」「確認待ち」等は維持し、内部処理を説明するHOTL・モデル・処理回数などの表記を画面から整理しました。検索の追加料金の表示も利用画面から削除しました。検索サービスの使用料は従来どおりOpenRouterの運用費に含まれ、検索機能・運用側の費用は変更していません。

原稿レビューのガイドは淡い背景と濃い文字に変更しています。進捗は画面上部の全体の完了率と6工程のカードで示し、各作業が終わっていても人による確認が必要なら「確認待ち」を表示します。作成中の工程だけを動きのある表示にし、OSの視覚効果抑制設定を尊重します。

各文章欄にファイル読み込み・貼り付け・コピー・保存を追加しました。Word（.docx）、UTF-8のテキスト（.txt/.md）、CSV（.csv）をページ内で読み込みます。Wordは本文の段落を文章として取り込みます。画像、ヘッダー、フッター、脚注、コメントや複雑なレイアウトを取り込む機能ではありません。PDFと旧形式の.docには対応していません。サイズ上限は500KB、各欄の文字数と資料全体80,000文字の上限を維持しています。文章やWordの展開後データにも上限を適用し、認証情報や読み取れないファイルを拒否します。Wordの変換サービスは使いません。

「入力内容を保存」で企画を保存し、「企画ファイルを読み込む」で入力のみ再利用できます。送信同意・機密区分・モデル・公開承認・制作状態はファイルから読み込めず、検索の使用もファイル取り込み時にはオフにします。企画は入力用のJSON形式で保存し、利用者は画面から保存・読み込みするだけで利用できます。記事や作業の内容は読みやすいテキストでコピー・保存できます。制作記録の保存と承認後の入稿用ファイル保存は従来どおりです。

ファイルはページのメモリで処理し、読み込みだけでAIへ送信することはありません。コピー・保存した元資料は利用者が手元で管理してください。ブラウザのクリップボード読み取りが許可されない場合は入力欄へ案内し、通常の貼り付け操作を利用できます。

検証: `npm test`、`node tests/usability-browser.mjs`、`node tests/workflow-browser.mjs`、`node tests/browser.mjs`、`node tests/dashboard-browser.mjs`。有料AIの呼び出しはモックです。
